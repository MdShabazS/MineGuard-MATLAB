## Files
- `matlab/+mineguard/+app/openMissionApp.m`: the **frozen API** `app = openMissionApp(runBundle)`. It validates **before** any UI is created, and invalid input throws `mineguard:InvalidRunBundle`.
- `matlab/+mineguard/+app/MissionApp.m`: a programmatic `uifigure` app, using the documented **source-backed fallback** rather than a binary `.mlapp` so it can be reviewed and diffed. It provides the state machine, rendering, playback timer, export and a test-facing `viewState`.
- `matlab/+mineguard/+app/makeRunBundle.m`: the **redacted runBundle adapter**, which copies allowlisted fields only. Evaluator match pairs are dropped, and provenance defaults to `NOT_RECORDED`.
- `matlab/+mineguard/+app/validateRunBundle.m`: strict schema, identity and privacy validation, with a recursive scan for truth names and stray tables.
- `matlab/experiments/makeMG011DemoBundle.m`: builds a **real** replay bundle:

## Redacted runBundle (implemented adapter; MG-010 §2.2)
- **Required fields:** `schema_version`, `scenario_id`, `geometry` (ScenarioGeometry), `poses` (PoseSample), `thermal_samples` and `em_samples` (11-column SensorSample), `events` (12-column DetectionEvent), `provenance`.
- **Optional fields:** `result` (the frozen 21-field ExperimentResult), `result_report` (aggregates only), `coverage` (MG-005 `computeCoverage` values), `route_enu_m` (MG-005 planned waypoints), `display_settings` (`grid_spacing_m`), `comparison`.
- **Rejected:** any other top-level field (restricted wrappers such as `hidden_truth`, `config`, `environment`, `private`). Also rejected: truth field names at any depth of a nested struct or cell, tables outside the four typed slots, extra pose/sample/event columns, scenario or schema mismatches, duplicate IDs, non-monotonic or non-finite times, sample→pose or event→sample references that don't resolve, channel/unit or invalid-reading violations, and any event status other than `SUSPECTED`.

## Dashboard behaviour (as implemented)
- **Layout:**
  - Header: scenario, replay state, simulated t, model version.
  - **Persistent red banner:** "SIMULATION — synthetic data; not validated for real landmine detection or clearance."
  - Left: controls and virtual telemetry.
  - Centre: the ENU map with bounds, exclusions, planned waypoints, visited cells (MG-005 cell rule), the trace up to t, an optional "Full Run" overlay, the UAV marker and SUSPECTED event markers at the estimated positions.
  - Right: the thermal (K) and EM (normalized, dimensionless) axes with invalid markers and reason subtitles, plus the events table.
  - Bottom: run metadata/provenance, and the aggregate synthetic evaluation (cell-level, with undefined ratios shown as "Undefined (zero denominator)"; localization kept separate; PPO comparison NOT RUN; 3-D view NOT AVAILABLE).
- **State machine:** IDLE → READY → RUNNING ⇄ PAUSED → COMPLETE; plus FAILED and CLOSED.
  - "Play Simulation", Pause, Step (exactly one stored pose), Reset (no regeneration), Seek (slider; deterministic reconstruction up to t), Speed (0.5×–20× simulated seconds per wall second, wall-clock based), and Export.
  - Buttons are enabled only in valid states. An empty run shows EMPTY with play, step and seek disabled.
- **Playback:** a `timer` (fixedSpacing, 0.1 s, BusyMode drop) with a reentrancy guard and `drawnow limitrate`. Rendering skips frames, never data.
  - The events table is redrawn only when the visible set changes; this was measured as the dominant cost, about 0.47 s per redraw.
  - The timer is stopped and deleted on close or reset.
- **Export:** to a user-chosen folder, or a cancel (0 or ""). Files are written first to a temp folder, then **read back and verified**, then moved into place:
  - `poses.csv`, `thermal_samples.csv`, `em_samples.csv`, `events.csv`: row counts and headers checked
  - `summary.json`: banner, UTC creation time, provenance, row counts, column names, events note
  - `run_bundle_redacted.mat`: `isequaln` round trip
  - `snapshot.png`: via `exportapp`

  On any failure the temp folder is deleted and no export is claimed.

**Development defects found by running the GUI, then fixed:**
1. `image` has no `DisplayName` (or `Annotation`) property in R2026b, so the constructor errored. The property was removed, and the constructor now deletes any half-built figure on failure.
2. The `Visited` property was declared `logical`, which silently converted cell indices to `true`, so seek errored. Changed to `double`.
3. Render took about 0.78 s per tick, because the `uitable` was rewritten every frame (profiled). The table is now cached by visible-event key, and legends no longer auto-update.
4. Replay "1x" ran slower than real time, because it advanced a fixed 0.1 s per tick. It now advances by measured wall time.
5. Readability: underscores rendered as subscripts, the events table overflowed, and some labels were truncated.

Known limitations:
- **SIMULATION ONLY.** The app replays precomputed synthetic runs. It does not run simulations from the UI (that is MG-015), does not control any vehicle, and has no telemetry or network link.
- This is a 2-D view only. The optional 3-D `uavScenario` view and the PPO comparison are feature-gated as NOT AVAILABLE / NOT RUN.
- The source-backed `uifigure` app is used instead of a binary `.mlapp`.
- Measured performance comes from this one Windows machine only. **macOS GUI: NOT TESTED.**
- Launching the app takes several seconds the first time in a session (about 10 s for the first `uifigure`).
- The events table omits the method column (method and threshold are shown in the metadata panel). Confidence is never presented as a probability.
- The demo replay uses an MG-009 TEST scenario that has already been inspected. It is a replay for display only, with no retuning.
- GitHub CI does not run MATLAB. All results above come from local R2026b desktop runs.
