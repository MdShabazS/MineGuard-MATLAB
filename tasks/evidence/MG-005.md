## Design (as implemented)
- **Route:** survey cells evenly subdivide the bounds (pitch ≤ `grid_spacing_m`). Waypoints sit at cell centres in serpentine rows: east-west, alternating direction, stepping north. The route height is `z_up_m = altitude_m`.
- **Exclusions (AT-10):** cell centres inside exclusion polygons are dropped. Every leg is then checked with an **exact segment–polygon intersection test** (`private/segmentHitsPolygons.m`, using orientation tests; no point sampling). Entering, crossing or touching a polygon edge or vertex gets `mineguard:RouteConflict`, in both `makeGridRoute` and, independently, `simulatePose` for routes users supply themselves. This is reject, not reroute.
- **Kinematics:** a point mass at constant `speed_mps` with instant turns at waypoints, constant altitude and roll = pitch = 0. `yaw_rad` is the ENU heading, measured counter-clockwise from east. Samples are taken every `dt_s` from t = 0, plus a final sample at the end of the route. Mission states run `INIT → SURVEY → COMPLETE`.
- **Virtual geotag (FR-05):** only when a virtual origin is configured. Uses a flat-earth projection (R = 6378137 m) with optional Gaussian `gps_sigma_m` noise from a local `RandStream(navConfig.seed)`. Without an origin, the geotags and `gps_sigma_m` are NaN, as the contract requires. The coordinates are SYNTHETIC.
- **Firewall:** `validateNavConfig` whitelists the NavigationConfig fields and rejects anything else (`mineguard:InvalidNavigationConfig`). `validateGeometry` requires exactly the 6 frozen geometry fields (`mineguard:InvalidNavigationInput`).
- **UAV adapter:** ENU poses are converted to NED for a `uavPlatform`, moved with `move` and `advance`, then read back and converted to ENU.

Known limitations:
- **SIMULATION ONLY.** This is a point-mass kinematic baseline with no flight dynamics, wind, battery, turn-rate limits or take-off and landing. It is not evidence of physical autonomous flight (see ACCEPTANCE_MATRIX O1).
- Exclusions are handled by rejection only. An interior exclusion that splits a row gets `RouteConflict` rather than a detour; constrained rerouting is not implemented.
- Coverage counts a cell as visited when a pose sample falls inside it. It does not model a sensor footprint; footprints belong to MG-007.
- The virtual geotag uses a flat-earth approximation that suits small synthetic fields. The coordinates are not real GNSS.
- The `uavScenario` replay is kinematic: the pose is set each step, so it is not an autopilot. A 3D view is available with `show3D(scene)` but was not captured, because the tests run headless.
- The `ABORTED` state is defined but never produced by this baseline, which has no fault injection.

## PR #14 review fixes (commit `67abe83`)
1. `makeGridRoute.m`: the 0.1 m point-sampled leg check is replaced by an exact segment–polygon test. A leg is rejected if an endpoint is inside or on the polygon, or if it properly crosses, touches or runs collinear with any polygon edge. Tolerance is relative (1e-12 × scale²).
2. `simulatePose.m`: each leg of a route supplied by the caller is now checked on its own with the same test (`mineguard:RouteConflict`), even when all waypoints are outside the exclusion zones.
3. `validateGeometry.m`: a recursive scan of `terrain_model`, through nested structs and cells, rejects any field named in `mineguard.contract.truthFieldNames()` and any table (`mineguard:InvalidNavigationInput`). The list lives in the new `+contract` package, so the navigation source contains no truth field names and the C-05 source scan stays meaningful.
4. New tests:
   - `at10b_narrowPolygonBetweenSamples`: a 1 cm strip lying between the old sample points, and a vertex touching a leg.
   - `at10c_manualRouteExclusion`: a manual leg crossing a box, a leg running along a box edge, and a 2 mm square on a manual leg are all rejected. A legal perimeter route is accepted, and none of its poses fall inside the box.
   - `c05_nestedTruthInGeometryRejected`: nested `hidden_truth`, `label` inside a cell, a truth table, and a deep `burial_depth_m` are all rejected by makeGridRoute, simulatePose and computeCoverage. Harmless nested metadata is still accepted.
