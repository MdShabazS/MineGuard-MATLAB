## Environment design (as implemented)
- **Grid:** 10×10 m flat S0 field with 2 m cells, giving **N = 25** (5×5). Cell centres, pitch and ordering follow MG-005 `gridCells`. Cell ID = (iy−1)·nx + ix, starting at the SW cell. P-01 shows the centres equal the MG-005 waypoints.
- **Legality:** a cell is legal when its centre is outside every exclusion polygon. A leg i→j is legal exactly when MG-005's public `simulatePose` accepts it, which uses the exact segment/polygon test, so touching or narrow polygons are caught. Each leg's poses come from that same call.
- **Observation** (layout `cov-2N+5-v1`, 55×1, values in [0,1]): normalised x and y, visited mask (N), reachable mask (N), remaining time, remaining distance, elapsed time. **No truth and no sensor features.** The optional uncertainty feature is not implemented and is feature-gated: P-19 rejects it.
- **Action:** `rlFiniteSetSpec(1:25)`, the next cell ID. Malformed actions (NaN, non-integer, outside 1..N), unreachable cells and the current cell are **rejected**: the position is unchanged, a penalty of w_bad applies, and the decision still counts. The policy output is never silently replaced with a legal action.
- **Shared budget** (PPO and grid alike): D_max 60 m, T_max 30 s, at most 50 decisions, start at cell 1 (the first MG-005 waypoint), 2 m/s, 2 m altitude, dt 0.1 s.
  - A leg that would exceed the budget is not executed; the episode ends with `BUDGET_EXHAUSTED`.
  - Other termination reasons: `COVERAGE_GOAL`, `MAX_STEPS`, `NO_LEGAL_ACTION`.
- **Coverage:** a cell is visited when a sampled pose lies inside it, the same rule as MG-005 `computeCoverage`. Every episode's global pose table (unique IDs, monotonic `t_s`) is re-scored with `computeCoverage`.
- **Reward** (MG-012 §5, illustrative weights, **not tuned**):
  - `r = 1·ΔC − 0.1·ΔL − 0.1·ΔT − 0.02·revisit − 0.1·invalid − 0.001·step − 0.05·failure_end`
  - ΔC = new legal cells / N_legal; ΔL = leg / D_max; ΔT = leg time / T_max.
  - Every component is logged per step (`S.reward_log`).
  - There is **no target or truth term**: the scenarios contain zero objects, and the `+rl` code never references truth (P-03 source scan).
- **Fixed-grid baseline:** the unmodified MG-005 `makeGridRoute` output, executed through the same `stepSurvey` (same budget and coverage accounting). If MG-005 rejects the scenario (`RouteConflict`), the grid is **INFEASIBLE**. It is never rerouted, and no Δ is computed for that scenario.

- In the deterministic mode it can lock onto an invalid action.
- With 4 feasible pairs, statistical power is very low.
- **The fixed grid remains the release baseline.**

Known limitations:
- **SIMULATION ONLY.** This is a coverage-only waypoint selector on a flat 5×5 grid. It is not a flight controller and has no detection objective; its reward contains no target information. Nothing here suggests PPO improves mine detection.
- The PPO policy **underperforms** the fixed grid where the grid is feasible, and it showed one deterministic lock-up (7207). There are only 4 feasible paired TEST cases, so the intervals are indicative only.
- Reward weights are the MG-012 illustrative set and were **not tuned** on TRAIN/VALIDATION. Hyperparameters were set from two short exploratory runs on one scenario (300 and 1,200 episodes), done before the manifest existed. TEST was never used for any choice.
- The grid baseline cannot reroute around interior zones, so 6/10 TEST scenarios are grid-infeasible. PPO's results there are reported separately and are not comparisons.
- The console output of the full training call was lost when the Claude Code MCP client stopped waiting after 1,800 s. MATLAB itself finished the run, and every result was written to the files above at 22:07–22:08. The reload check is evidenced independently by P-14 and P-20.
- Detection metrics under PPO routes, sensor-uncertainty features, MG-014 GF families and dashboard integration are **NOT RUN**. They belong to MG-019, MG-014 and MG-015, each under its own run-lock.
- GitHub CI does not run MATLAB. All results come from the local R2026b runs.
