## Self-review

Self-review: done by the owner (Shabaz's Claude), plus a fresh reviewer subagent (findings below).
1. **Open buttons, never at start:** done. Satellite, field survey, cut/fill and relief are in the V2.1 Mission Setup window.
2. **Offline fallback with a notice:** done; never a blank map presented as imagery.
3. **Cleanup; follows reset, new run and replay:** done. The trail restarts on every new engine.
4. **Nothing else changes:** V2 files untouched. The V2.1 change is additive (two rows and a slot), and its setup tests pass.
5. **Measure:** startup and refresh numbers above, compared with V2.1 without v2_2.

Deviations:
- **Buttons, not a tab:** the buttons are in the Mission Setup window, which stays open during the run, rather than in the V2 dashboard. The dashboard is V2 code and is left unchanged.
- **Follow timer:** the overlay follows the session by polling every 0.25 s rather than by subscribing to the engine. A reset builds a new engine, and a subscription would add work to every mission tick.
- **Regression:** the full V2 regression is deferred to V22-T8 (Windows), as noted above.

Reviewer findings (fresh subagent; nothing blocked the merge). Fixed and tested:
1. **Orphan follow timer:** if the satellite figure was deleted from outside, the follow timer kept running, and pressing the button again made a second one. Now opening stops any old timer, and `poll` stops the timer when the window is gone.
2. **Failed open:** a failed first poll left a window that never followed the run. A failed open now closes the window, and pressing the button resumes following after an error.
3. **Replay route:** a replay of a different survey drew the route of the locked scenario. The overlay now follows the session's `MissionConfig`.
4. **Mission Setup X:** closing Setup with its window X left the BITM views open. They now close with it.
5. **Stale handles:** reopening a view after closing it with its window X kept the old handle object. It is now deleted first.
6. **Weak test:** a near-tautological check was removed.

Noted, not changed: the offline check uses the imagery service's metadata. Tiles can still fail after it answers, and the view then says "tile loading unverified". This limit is written in `SiteViews`.
