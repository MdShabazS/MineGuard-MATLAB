# V22-T6 — Satellite tab in V2.1 mission control, with offline fallback (owner: Rahil) · BUILD

**Goal:** the presenter opens the satellite view from the V2.1 app. It is optional and never slows the normal mission.

## Inputs

- T4, T5 and T9 modules in `v2_2/matlab` (T9: `mgv22.cutfill`).
- V2.1 app: `v2_1/matlab/mgv21MissionControl.m` and `+mgv21/+ui/` (`Launcher`, `RunController`).
- Offline fallback: `v2/enhancements/+mgenh009/renderOfflineCampusContext.m`.

## Steps (subagents: one for integration, one for fallback and its tests, one to measure performance)

1. **Open button:** add a "Satellite view (BITM)" button, or tab, to the V2.1 app. It opens the T4 preview with the T5 overlay bound to the running session. It must **not** open at app start.
1b. **Cut/fill tab:** add a second button or tab, "Cut/fill map (BITM)", that opens the V22-T9 view for the running session's survey. Same rules: never opens at start; closes cleanly.
2. **Offline fallback:** if the basemap fails or there is no network, show the ENH-009 schematic with "ILLUSTRATIVE / NOT SURVEYED / SIMULATION CONTEXT" and a notice. Never show a blank map.
3. **Cleanup:** closing the view or the app leaves no figures or timers. The view follows reset, new run and replay correctly.
4. **Nothing else changes:** the offline ENU mission map, detector, evidence seam, export/replay, sealed TEST data and V2/V2.1 results stay unchanged.
5. **Measure:** app startup time and mission refresh rate with the view closed and with it open. Compare against the V2.1 baseline and record the numbers.

## Tests

- New `v2_2/tests/testV22SatelliteTab.m`:
  - the button opens and closes the view;
  - the fallback appears on a simulated basemap failure;
  - the view follows reset and new run;
  - no leftover figures after 10 cycles.
- **Full regression** at the final SHA: V2, V2.1 and all `v2_2/tests`. Use the same list as `v2_1/evidence/V21-008/regression_*.txt`, plus `v2_2/tests`. Write the log to `v2_2/evidence/V22-T6/regression_<sha>.txt`.
