## 4. Recommended MATLAB architecture and acceptance

1. **Presenter-controlled entry point, no V2 core dependency.** After Shabaz approves anchor/viewport and source, use the existing #72/#75 standalone preview for the online campus context. Keep it distinct from the authoritative offline ENU mission map and 3-D simulation. Do not open the online basemap during normal V2-007 startup.
2. **Two static context views before any animation:** Ballari orientation with a licensed/attributed source or plain named card; then an approved campus crop with the exact banner **REAL IMAGERY — SIMULATED FLIGHT / NOT A HAZARD MAP** if real imagery is shown. Use the #98 storyboard only as a proposed presenter control. If tiles fail or rights are unresolved, switch to #95's original schematic with **ILLUSTRATIVE / NOT SURVEYED / SIMULATION CONTEXT**. Never let a blank/cached map masquerade as loaded satellite imagery.
3. **No fictitious georegistration.** Use one approved presentation-only approximate anchor with the existing conversion; treat ellipsoidal altitude separately and validate small-field ENU/WGS84 round trips against an independent known fixture. Route/home/boundary may come only from public mission state and must be labelled *planned virtual*. Do not place SUSPECTED events, mine icons, truth, evaluation metrics, or safety/clearance claims over real imagery. The handoff card closes context figures before the synthetic mission starts.
4. **Performance policy:** R2026b `geoaxes`/`geobasemap` are documented, but hosted tiles require internet; `addCustomBasemap`, `readgeotable`, GeoTIFF and MBTiles workflows are Mapping Toolbox options and must not become implicit requirements on either host. #75/#90 report checks on Mac/Windows, not ENH-008 integration frame cost. Measure startup, two-view transition and repeated open/close; use the existing roadmap's ≥0.8× provisional demo-quality criterion (preferred 1×) for any optional simultaneous view. If it costs too much, keep static cards and separate preview. No MATLAB performance value is claimed here. [MathWorks offline guidance](https://www.mathworks.com/help/map/use-basemaps-in-offline-environments.html) and [OSM-file base-layer example](https://www.mathworks.com/help/map/create-base-layer-from-openstreetmap-data.html) distinguish the base-MATLAB and Mapping Toolbox paths.

**Acceptance record at an exact implementation SHA:** Shabaz approves the location candidate and exact source/item rights in writing; store source URL, contributor credits, acquisition date, CRS and intended presentation/offline/repository scope. On Mac R2026b and Windows, verify online loaded-tile status, provider credits and banner at multiple zooms in light/dark themes; geodetic cardinal directions and route/footprint alignment; no real-campus anomaly overlay; network-denied fallback and reconnect; pause/resume and handoff boundary; repeated figure/timer cleanup; startup/frame cost against the live demo gate; screenshots and full test logs. Existing #75/#90 evidence covers the preview's reported checks, **not** this campus-specific acceptance. No new held-out detector evaluation is authorized or needed.
