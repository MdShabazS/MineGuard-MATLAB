**V2 is a working, deterministic simulation with a negative detection result, and it does not meet every acceptance criterion.** Of the 25 criteria, as measured against committed evidence:

- **17 PASS**, on Windows; a few also on a Mac at an older commit. These are AC-001, 002, 003, 004, 006, 008, 010, 012, 013, 014, 015, 016, 017, 018, 019, 020 and 021.

- **1 FAIL**: AC-025, the ≥ 10 FPS scene target.
- **2 NOT RUN**: AC-022 (Shabaz's personal Mac review) and AC-024 (Mac run of every MUST item).
- **1 PENDING**: AC-023, the V2-010 report.

Matrix §1 says a MUST item that cannot be done on macOS needs a formal revision with Shabaz and the guide. No such revision exists, so AC-022 and AC-024 stay open. **V2 is therefore not fully accepted under matrix Revision 1.0.** This audit does not revise the matrix.

## 3. Scientific results that must stay in every report

1. **V1 sealed held-out TEST (weighted fusion): TP 0, FP 26, TN 470, FN 4.** The detector missed all four positive cells (`V2-001.md`, `V2-004.md`, preflight §2). V2 does not overwrite it.
2. **V2-006 VALIDATION is negative.** G07, 4 targets: fused 45 events, TP 0, FP 45, FN 4; RGB-only 19 events, TP 0; thermal-only 9 events, TP 0. Target-free G08: 32, 4 and 1 false alarms (`V2-006.md` §4).
3. TRAIN, 15 targets: fused TP 2, FP 301, FN 13 (F1 0.0126). Fusion shows no advantage over thermal alone (`V2-006.md` §4).
4. DEMO FIXTURE: 78 events, TP 1, FP 77; the top-scoring event (score 1.000) is a false alarm (`V2-006.md`).
5. The live dashboard scenes contain **no synthetic target**. Every SUSPECTED event in a live run (84 in the nominal run) is therefore on target-free ground: a false alarm by construction (`V2-007.md`, V2-008 package manifests: `synthetic_targets_in_scene` = 0).
6. Scores and uncertainties are **uncalibrated**. A score is never a probability; sigma coverage was never measured (`V2-006.md` §8).
7. Georegistration uses the noise-free reference pose and exact terrain, so geometric results are optimistic. PR #93 (unmerged) reports a median 1.37 m navigation/reference displacement (`CODEX-V2-001-006.md` P1).
8. The track sigma counts the pose term twice: 0.1225 m against 0.1000 m, 22.5 % (`CODEX-V2-001-006.md` P1). `V2-006.md` §8 calls this "slightly"; 22.5 % is the measured figure.
9. **V2 held-out TEST (G09, G10) is sealed and was never run.** V2-008 did not run it either: the detector had already failed VALIDATION, and no further tuning was done.
10. **No real detection validation exists.** The thermal model is not calibrated or band-integrated; LiDAR is not scored; no result transfers to real sensors, terrain or targets.
11. Small evaluation: 2 VALIDATION groups, 4 targets, one mission per group. No confidence intervals, no false alarms per hectare.

## 5. Evidence defects found by this audit

These are recorded, not rewritten in the old files. Earlier evidence files stay as they were merged.

The defects below are recorded here; the earlier files are left as merged.

1. **Stale status wording.** `V2-001.md` L7 says "NOT DONE until …". `V2-004.md` L7 says "Proposed for independent review". `V2-006.md` L277 and L351, and `V2-007-bridge-stage3/README.md` L3 and L153, say "stays IN_PROGRESS". `status.json` on `main` is authoritative: V2-001 to V2-008 are DONE.
2. **Who ran the Mac runs.** `V2-006.md` L326 says "Shabaz's Mac run". `V2-006-mac-display/README.md` L5 says Claude Code executed it on Shabaz's Mac, with human review pending. Only the V2-002, V2-003 and V2-005 Mac results were run by Shabaz in person.
3. **Unpinned Mac runs.** The V2-002 and V2-003 Mac results have no git SHA, `ver` output or screenshot (`V2-002.md` L189, `V2-003.md` L223).
4. **10 FPS wording.** `V2-003.md` §8 item 5 says frame times are "within the ≥ 10 FPS target", yet the effective rate measured in that file was 9.9 FPS (L141).
5. **checkcode records.** `V2-007.md` L30 says "no messages", but its log line is only "checkcode done". From V2-008 on, the count per file is logged.
6. **Benchmark commit.** V2-007's benchmark ran at `c1c1580`, before its final `RefreshTicks` default; the record says so. V2-008 benchmarked `bddb4c2`, which differs from its final `4a7f63b` only in a notice reset.
7. **Missing log.** `regression_batch_2bca2f8.log`, cited in `V2-007-bridge-stage3/README.md` L179, is not in the tree.
8. **Transcribed logs.** Some V2-006 regressions are summaries or transcriptions, not full logs (`V2-006.md` L183–L190), and V2-006 was not rerun on its final commit. Its suite has since passed on `main` at `4a7f63b` (28/28).
9. **Uncertainty wording.** `V2-006.md` calls the track-sigma double count "slight"; it is 22.5 % (§3 item 8).
10. **No human tester.** Matrix §5 asks for an actual human tester. V2-007 and V2-008 were run by Claude Code, and both files say so. The tester line is honest, but the requirement is not met.
11. **Dated preflight document.** `V2_INTEGRATION_ACCEPTANCE_PREFLIGHT.md` L25 shows 5/10 DONE. It is a dated preflight document, not a status source.
