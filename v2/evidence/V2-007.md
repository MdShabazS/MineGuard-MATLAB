Paced 1x, three alternating rounds, fresh MATLAB, normal priority, full missions, at `c1c1580`. `095d7fb` afterwards changed the bridge default to the measured 100 and made the plain launcher use the bridge; the benchmark was not repeated, because it set the interval explicitly. - 100 ticks meets 1x within about 1%. 20 ticks falls about 22 s behind but still clears the provisional 0.8x minimum.
- **Cost:** the event list can be about 5 simulated seconds old between rebuilds. The panel shows the age, and it is flagged above 5.5 s. Ticks decide rebuilds, and both settings gave 84 events at the end of a run.
- **Target not met:** the provisional scene target is >= 10 FPS. With the detector the display refreshes 6.3-6.5 times per second. This is recorded as measured, not passed. Skipped updates are display only; physics and sensors were not skipped (identical digests).
- Stalls up to 774 ms occur; a detector rebuild takes about 455 ms at p95.

## 4. Defects found and fixed in the final review

An automated Claude review (not a human) read the integrated code. The fixes, with a test where noted:
- A source error during a tick froze the display on ACTIVE, and a later resume lost samples without a report. The run now ends as ABORTED with `SOFTWARE_FAULT` and shows the error (test).
- The map ring stayed at an old estimate or a removed event (test).
- A source that refused a run left the session half built. The mission now flies with sensors, and the refusal stays on screen (test). A failed `configure` restores the previous settings (no test of the restore path).
- Rejected events were shown in the valid colour (test). Evidence time, pose and sensor are now compared with the log (test).
- A plain `mgv2MissionControl` opened with **no detector**, because the earlier check always passed one in. It now uses the real bridge (test), and `app_check.m` launches it that way.
