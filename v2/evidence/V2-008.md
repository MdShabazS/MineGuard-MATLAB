## 2. What was built

| Part | File | What it does |
|---|---|---|
| Recorder | `+mgv2/+run/Recorder.m` | Keeps every sample of a live run, in emission order, in memory |
| Digest | `+mgv2/+run/digest.m` | SHA-256 over a canonical byte form of a value (class, size, raw bytes, sorted fields); the same after a MAT round trip |
| Export | `+mgv2/+run/exportRun.m` | Package `mg-v2-runpkg/1.0`: manifest, configuration, every pose, every sample per sensor, sample index with digests, events, verified evidence of every event, `files.sha256`. Written to a hidden `.partial-` folder and renamed only when complete; never overwrites; any failure removes the partial folder and raises an error |
| Verify | `+mgv2/+run/verifyPackage.m` | Refuses a package whose file set or any file hash differs from `files.sha256`, whose counts differ from the manifest, whose samples fail `validateSample`, whose sample digest or producer checksum differs from the index, whose poses have gaps, or that holds a forbidden truth name |
| Reproduce | `+mgv2/+run/reproduce.m` | Simulates the package's configuration again, headless, and compares every pose (bit for bit), every sample digest and the end state |
| Replay | `+mgv2/+replay/PlaybackEngine.m`, `PlaybackSensors.m` | Play the recorded poses and samples on the same tick clock through the same anomaly source; nothing is simulated or re-seeded |
| Session | `+mgv2/+ui/MissionSession.m` | `exportRun`, `loadReplay` (a refused package leaves the session unchanged), `replayCheck` (replayed events must equal the recorded events), two new scenarios |
| Controls | `+mgv2/+ui/ControlBar.m`, `MissionControlApp.m` | EXPORT is enabled once for an ended live run; REPLAY when no run is active; a notice line shows the export folder, the replay result, or the reason for a refusal in the invalid colour; the readout says "REPLAY (recorded, not simulated)" |
| Scenarios | `MissionSession.Scenarios` | "Invalid rays": RGB and LiDAR measure only to 16 m at 15 m AGL, 20 % LiDAR ray dropout. "Mission fault (timeout)": a timeout 2 s above the engine's preflight lower bound, so the flight overruns and FAILS with TIMEOUT |

Detector, thresholds, sensor models and frozen data are unchanged. The simulation is unchanged: all benchmark missions give the same sample and pose digests as V2-007 (`01696119`, `e649b54c`).

To check it:
```matlab
addpath('v2/matlab'); pkg = mgv2.run.verifyPackage('v2/evidence/V2-008/sample_package/V2RUN-NOMINAL-0001_g1_20261103T151722Z');
r = mgv2.run.reproduce(pkg)          % r.match must be true

```
`sample_package/.gitattributes` keeps git from converting line endings, which would change the file hashes.

**Correction (release audit, 2026-11-03):** the repository `.gitignore` excludes `*.mat`, so the first commit of this package (#106) silently omitted its eight MAT-files. The clean-clone release audit found it: `verifyPackage` refused the package as tampered (missing files). A narrow `.gitignore` exception and the eight files, byte-identical to the hashes in `files.sha256`, were added afterwards. The package itself and its recorded results are unchanged.

## 8. Known limitations and not run

- **macOS: NOT RUN.** AC-024 is not met. Package hashing uses Java, present in every desktop MATLAB, but this was not tried on a Mac.
- **No human** watched any run here. Screenshots were captured by script and looked at by Claude Code.
- `files.sha256` detects changed, missing or extra files and edited samples; it is **not a signature**. Someone who rewrites the index, the manifest and all hashes consistently is not detected.
- A full nominal package is large (§7); export takes seconds and needs that much free disk. Memory during a run grows by about 0.4 MB per simulated second.
- Replay shows the recording; it does not check the simulation. `reproduce` is the determinism check and runs headless.
- Replay of a package needs the same world (`world_digest`); a package from another world is refused.
- The detector's science is unchanged: no detector, threshold or frozen data file changed, and no TEST run was made.
