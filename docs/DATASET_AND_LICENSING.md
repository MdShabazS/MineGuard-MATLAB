## 2. Dataset acceptance checklist before ingestion
- Real landing page, persistent DOI or verified institution; uploader identity and dataset description.
- Rights allow academic analysis and redistribution? Record a verbatim licence link, attribution requirements and restrictions. If unclear, link externally rather than re-hosting images.
- Check resolution, sensors, camera distance, burial conditions, acquisition dates, background/clutter, any train/test split and ground truth provenance.
- Document data integrity (SHA256), sample counts and accidental duplicates/near-duplicates.
- Separate paper training/test figures from our experiments; rerun independently if claiming project performance.
- Avoid protected operational minefield coordinates, harmful instructions or personal identification in public records.

## 3. Synthetic data generation contract
Scenario input includes scenario identifier, soil class, thermal properties, target material (coarsely), burial depth, target location, camera footprint, altitude, coil standoff, time of day, noise seeds and class imbalance. All stochastic parameters must be generated from saved RNG seed; labels are stored *only* in `TargetTruth` and evaluation pipeline, never passed to model feature constructor.

### Ground-truth split
- Training seeds, validation seeds and held-out test seeds disjoint and saved. Group all derived noise seeds, near-duplicate frames, augmentations and repeated passes of the **same base scenario layout** into one split.
- If one scenario has multiple nearby sensor frames, group them by scenario/target so duplicate frames never cross splits.
- Feature scaling/statistics learned only from training data.
- Synthetic simulator hyperparameters not retuned on final held-out set. Choose temporal alignment, event clustering, matching radius and decision thresholds using train/validation only, then freeze prior to test. Keep cell-level confusion separate from object-event localization matching.

## 4. Synthetic vs real domain gap
Even 99% accuracy on clean synthetic data could be meaningless on real field data. State 'synthetic test accuracy' explicitly, run stress tests with altered soil/noise and reveal failures. Calibrated real-world probability requires independent representative measurements and validation, not just a trained classifier.

## 5. Repo storage policy
- Store code to regenerate data, small synthetic representative fixtures and configuration/seed values in GitHub.
- Do not commit large unlicensed image datasets, MATLAB install media, licence files or full trained checkpoints unless compliant with repository limits and permissions.
- Large accepted artefacts: use documented external versioned storage or Git LFS after explicit team decision. Record SHA256 and provenance in GitHub.

## Verified 2026 multimodal data candidate — DRC Seeded Field
- Publisher record: https://zenodo.org/records/19100554 (version v2, 2026-03-18), DOI: https://doi.org/10.5281/zenodo.19100554. Creators include Baur, Steinberg, Lekhak, Nikulin, de Smet, Ientilucci, Brinkley, Myers and Nitsche.
- Collected across field seasons 2023–2024 with UAV RGB/thermal/multispectral and handheld induction/metal detector/other sensors. Examples on page: thermal Autel EVO II Dual at ~12 m AGL and **handheld** MineLab / EM61-Lite at ~0–0.3 m. Different platforms, heights and contexts mean measurements may **not** be aligned as ready-made sample-wise paired training observations.
- **Licence not yet established:** Zenodo page's Rights/License heading did not expose an actual licence identifier to this research session. The record says “Open” but access status is not a substitute for a redistribution licence. Verify metadata/permission directly before copying bytes into public GitHub.
- The record contains large GeoTIFF imagery; do not fetch every file automatically. Select one relevant small sample only after licence/format checks, preserve checksums and attribution, and confirm that data are inert research test records rather than operational minefield material.
- **No dataset downloaded, parsed, paired or experimentally used as of the documentation audit.** Candidate is not a completed benchmark.
