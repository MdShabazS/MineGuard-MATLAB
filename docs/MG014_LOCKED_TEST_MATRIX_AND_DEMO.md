## 2. Preregistered scenario groups — machine-readable lock

**Canonical predeclared manifest:** [`experiments/locked/mg014_scenario_manifest.json`](../experiments/locked/mg014_scenario_manifest.json) with `mg014-scenario-lock/1.0` and `plan_status=PREDECLARED_NOT_GENERATED`. This is a **locked evaluation plan**: actual scenarios, feature statistics, model files, run outputs, and tests have **not** been generated by MG-014.

Exactly **30 distinct scenario-family groups**, 6 profiles per split-balanced block:

| Split | Group IDs | Count | Permitted use |
|---|---|---:|---|
| TRAIN | GF-001 … GF-018 | 18 | Fit feature normalization, background parameters and model weights; calibrate **only according to MG-008** |
| VALIDATION | GF-019 … GF-024 | 6 | Select thresholds, event-clustering/matching tolerances, missing-modality policy and optional PPO checkpoint before TEST |
| SEALED TEST | GF-025 … GF-030 | 6 | Once-only frozen final evaluation; not allowed for tuning, threshold fitting, early stopping, manual example selection or backfilling failed runs |

The six profiles repeat in each complete six-group block (each profile occurs 3 TRAIN + 1 VALIDATION + 1 TEST): **negative_empty** (0 target / 0 clutter), **single_target** (1/0), **target_plus_clutter** (1/2), **clutter_only** (0/2), **two_targets** (2/1), **weak_standoff** (1/1 and a higher altitude). Every profile contains *synthetic surrogate objects* or deliberately none. A target count or profile label is **evaluator/generator-only** and **must not appear in navigation, detector, policy, dashboard inference inputs or public prediction files**. Do not force detector success on weak standoff or ensure at least one hit.

**Base configuration plan:** 20×20-m local ENU rectangle with flat datum and no exclusions; `grid_spacing_m=2`, actual 10×10 = **100** planned legal cells for the unexcluded profile; `dt_s=0.1`, `sampling_hz=10`, `speed_mps=2`, `altitude_m=2` (5 only for `weak_standoff`); 0.5-m object separation; `soil_class=synthetic_loam`; `mg-contract/1.0`. These are *test configuration choices*, not physical performance claims. Every row supplies explicit, distinct `seed`, `noise_seed`, `scenario_id`, family ID and split. MG-004's documented derived thermal/EM/navigation seeds come solely from each noise seed; there is no crossing of scenario/noise family across splits.

**Protocol constraints:**
1. Generate full `ExperimentConfig` by applying the base fields and named profile to each exact manifest row, not by regenerating new seeds in response to failures or selecting best-looking trials.
2. Keep all replays, frame segments, data augmentation and sensor noise replicates belonging to a scenario **within that family’s split**. Negative and positive examples alike must stay grouped; compare methods on identical held-out scenario/route/measurement conditions.
3. **Before opening the sealed TEST:** commit a versioned lock record listing complete sensor settings and limits, software Git SHA, generator/model versions, split manifest hash, model/normalizer/checkpoint SHA(s), threshold/association tolerance, cluster radius, evaluation cell rule and localization matching radius; verify all are populated and runnable. The MG-006 synthetic parameters need actual documented settings from MG-007, not placeholders. If absent, the evaluation is **BLOCKED**; do not improvise values on the test run.
4. Lock the expected `schema_version`, ENU axes, sampling units, legal/exclusion-cell determination and measurable dropout policy. Use the same `DetectionEvent` and `ExperimentResult` fields as MG-003. The optional `DetectorConfig.missing_modality_rule` spelling was clarified for MG-009 as `abstain|single_valid|require_both`; verify that the tested implementation and evidence match.
5. Save generated-scenario configuration digests before TEST. **Do not commit target truth inside public event/replay datasets**. Evaluator-only truth and private match tables must remain separate. A public manifest may declare synthetic class mix for experimental design, but it must never be passed to inference as a predictive feature.
6. If a frozen case fails to generate, is not physically evaluable under the model, or a program bug arises, record the actual failure/abort; do **not replace the TEST scenario**. A required technical correction changes the code/version and mandates a reviewed amendment and clean rerun of the affected predefined suite, not silent selective re-testing.
7. A predeclared profile is not proof of **a specific** material (e.g. rock vs metallic debris). MG-004 uses seeded random clutter types. Dedicated deterministic negative-control fixtures must assert the requested clutter material **before** using it for an exact material-specific test. If no such fixture exists, mark the case BLOCKED instead of assuming a randomly drawn material.
8. TEST may be inspected once for final evaluation; any subsequent code change or exploratory re-run must be reported as post-test analysis rather than an untouched held-out score. All scenario families and source code versions are recorded.

## 4. Metric and analysis lock — mathematical definitions

**Primary unit:** one legal, *evaluable*, visited survey cell; do not treat never observed or invalid-only cells as true negatives. For a cell `positive iff TargetTruth.label=="target" present` and `predicted positive iff ≥1 valid SUSPECTED event in cell`. Declare the assignment half-open boundary rule, total legal count, visited count, valid/evaluable count, excluded count, class prevalence and per-modality assessability before TEST. Fusion methods with different missing rules may have different evaluable-cell populations—report that difference and optionally re-evaluate on a **common intersection** of cells, explicitly labelled.

```text
precision = TP/(TP+FP)              when TP+FP>0, else NaN
recall    = TP/(TP+FN)              when TP+FN>0, else NaN
F1        = 2TP/(2TP+FP+FN)         when denominator>0, else NaN
FPR       = FP/(FP+TN)              when FP+TN>0, else NaN
coverage  = visited_valid_cells / total_valid_cells
```

Record all denominators and empty population; pooled (micro) totals and per-scenario (macro) dispersion **separately**. *Event/object* matches use one-to-one max-cardinality tolerance and a separate report of matched events, missed objects, unmatched alarms and localization distance. These counts **never** replace cell-unit TP/FP/TN/FN or invent a true-negative object population. `confidence_0_1` is a model score unless separately calibrated on TRAIN/VALIDATION with recorded provenance; NaN is allowed.

**Frozen model selection:** train normalizers/background on TRAIN; choose thermal threshold, EM threshold, fusion weight and rule, association tolerance, clustering window/radius, event localization tolerance and optional probability calibration on VALIDATION only; record model hashes before opening TEST. All five methods must use the same scenario/pose/noise/sample conditions on held-out data, and any sensor physical-domain limitation must remain visible. For high-standoff cases, "not assessable" is not a detection success.

**PPO E5 conditional:** if a checkpoint exists, select it on VALIDATION and compare on the same held-out GF-025..030 families, starting cell, altitude/speed/motion, legal region, same `D_max` and `T_max`. *Suggested predeclared budget for the no-exclusion 20×20 m, 2-m cells fixture only:* `D_max=250 m`, `T_max=125 s` at `speed_mps=2`; max 120 waypoint decisions for both strategies if both use this concept. Freeze and validate both implementations against this plan before TEST. Any incompatible travel budget must trigger an explicit reviewed protocol amendment. Compare paired `C_PPO-C_GRID`, `D_PPO-D_GRID`, `T_PPO-T_GRID`, count constraint violations, incomplete routes and show scenario-level variance. No PPO evidence → skip that comparison rather than mock a chart.

**Stress design (separate labelled reports, not added post-hoc to ordinary test denominator):** E2 physically model-limited standoff/altitude, target burial depth, signed thermal contrast, ambient/soil parameters, clutter variants, sensor noise/dropouts, timestamp skew and geotag uncertainty. The exact sweep grid and sampling budget must be frozen with the final settings lock before execution. If no settings lock exists, mark corresponding experiment as NOT RUN, not "sweep completed."
